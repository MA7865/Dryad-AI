# M1 - Forest Health

**Status: working end to end, with documented limits.** Satellite and climate data from Earth Engine, a trained model, and an API. The model was tested on map areas and years it never saw.

## What M1 delivers
For each of the 2,061 Shaver Lake patches:
1. **Condition index** (0-100) and band: greenness and moisture relative to unburned forest in the area. It is **not** a mortality predictor.
2. **Mortality likelihood** from a trained model: the relative likelihood that USFS aerial surveys would map tree mortality in the patch, with a band (Lower / Elevated / High) and a percentile among scored Shaver Lake patches. Scored for the latest completed summer.
3. **5-summer trend** (2022-2026) relative to similar patches. Context only.
4. NDVI, NDMI, per-summer history, burn status and data quality.

## How it works
- Live refresh (every 6 hours while the API runs): the newest 30-day Sentinel-2 window gives the condition index; the latest completed summer's features give the model score. Results are held in memory; generated files go to `data/cache/` (not in Git).
- Model: gradient-boosted trees on 16 features (terrain, tree cover, climate, Sentinel-2 summer indices and their change), trained on 51,641 labelled patch-years from 15,457 USFS mortality polygons across the Sierra Nevada, 2021-2024. Shaver Lake was never used in training.
- Climate inputs come from TerraClimate, which currently ends in 2024, so the pipeline uses the latest year available and reports it (`mortality_climate_year`).

## Evidence (full tables: `docs/M1_MODEL_CARD.md`, generated from the model card)
- Whole 20 km map blocks held out: AUC 0.78 (95% interval 0.77-0.80). The 10% of patches flagged most strongly were mapped as damaged 69% of the time, against 25% overall.
- Shaver Lake, never seen (683 patches, 99 damaged): AUC 0.71; top 10% flagged: 29% damaged versus 14.5% overall.
- Predicted and observed rates agree within about 0.02 in every decile.
- Terrain and climate alone nearly match the full model. In whole-block testing, satellite features add about +0.01 AUC (0.764 to 0.776; interval +0.008 to +0.016). In the strictest test (new places and a new year; 2,049 patches, 364 damaged) the two models cannot be told apart (0.72 environment-only vs 0.68 with satellite; difference interval -0.09 to +0.02), and the sign changed between two software environments, so no satellite gain is claimed there.
- Features recomputed through the live code path match the training table to 5 decimals on all 2,061 patches.
- Condition index: does not flag surveyed damage (AUC 0.18 in the 22-polygon box). Trend: AUC 0.54 (before the survey year) and 0.61 (including it): context only.
- Automated tests: 15 (the live Earth Engine test is optional).
- Latest run: 753 patches scored, 1,243 burned (not scored), 65 with too little forest. Against Sierra-wide cutoffs all 753 fell in the Lower band (Shaver Lake is lower-risk than surveyed Sierra forest on average); the API also returns a percentile among Shaver Lake patches for local contrast.
- At Shaver Lake the mean predicted likelihood for labelled patch-years was 0.154 against an observed damage rate of 0.145, and observed damage rose across thirds of the score (2.6%, 16.7%, 24.1%). Year-level intensity is not captured: 2021 and 2024 were over-predicted (0.17 vs 0.03 and 0.07 vs 0.01) and 2023 under-predicted (0.13 vs 0.19). Use the model to rank patches, not to forecast how much damage a given year will bring.

## Risks and limits
- Predicts where USFS surveyors map mortality (mostly bark beetles), not general forest health.
- Most skill comes from terrain, tree cover and climate.
- "No polygon" may mean "not surveyed" (the survey service has no flight-coverage layer); negatives are cells within 3 km of a polygon.
- The likelihood is relative to surveyed forest, not a real-world probability.
- Climate data lags real time by more than a year; Shaver Lake accuracy rests on 99 damaged patches.
- The burn flag is coarse (MODIS 500 m); the forest mask is from 2021.

## How to run
```
pip install -r requirements.txt        # pins scikit-learn: the saved model needs the same version
python -m modules.forest_health.build_outputs
uvicorn backend.app.main:app --reload  # open http://127.0.0.1:8000/docs
```
Live data needs Earth Engine access (`earthengine authenticate`, set `EE_PROJECT`). Without it the API still serves the summer layer and the model card; `M1_LIVE=off` disables live calls.
Retraining: `scripts/` (fetch_ids_sierra, make_training_cells, extract_training_features, train_baselines, train_final, make_model_card_md). The training data is not in Git and takes about 30 minutes to regenerate.
