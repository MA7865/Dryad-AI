## What M3 does

M3 is responsible for estimated ignition risk for the 2,061 permanent 500 m
patches in the Shaver Lake study area. It also provides a what-if weather
scenario layer.

Phase 1:

- creates the public M3 interfaces
- shares grid lookup with M4
- fetches forecast and historical weather
- prepares a per-patch static terrain/fuel table
- serves a clearly labelled untrained stub
- validates scenario inputs
- provides M3 Pydantic/OpenAPI schemas

Phase 1 does not train a model, download FIRMS history, or produce risk values.

### Scenario validation

Request fields:

- `valid_at`: optional UTC ISO 8601 string
- `delta_temp_c`: `-10` to `10` C
- `delta_wind_pct`: `-50` to `100` percent
- `delta_precip_pct`: `-100` to `100` percent
- `patch_ids`: optional list; `null` means all patches

Out-of-range or non-finite values return HTTP 422 with a plain FastAPI
`detail` string.

### Unknown patch and service errors

- Unknown patch: HTTP 404, detail `Unknown patch_id: <id>`
- Grid unavailable: HTTP 503
- Weather service failure: HTTP 503 with `Retry-After: 60`
- Missing values: `null`, never fabricated zero or NaN

## Weather implementation

The shared client returns hourly rows with:

- `temp_c`
- `rh_pct`
- `wind_speed_ms`
- `wind_gust_ms`
- `wind_dir_deg`
- `wind_toward_deg`
- `precip_mm`
- `precip_24h_mm`
- `precip_7d_mm`
- `precip_30d_mm`
- `vpd_kpa`

Rules:

- Wind speed: meters per second at 10 m
- Temperature: degrees Celsius
- Relative humidity: percent
- Precipitation: mm per hour
- Wind direction: FROM
- M4-compatible direction: `wind_toward_deg = (wind_dir_deg + 180) mod 360`
- API time: UTC

VPD fallback formula:

```text
es = 0.6108 * exp(17.27 * T / (T + 237.3))
vpd = es * (1 - RH / 100)
```

Open-Meteo is also supported in historical/archive mode. The history call
includes 30 days of lookback so 7-day and 30-day precipitation sums can be
computed. Live-network tests are optional and skipped by default.

## Static terrain and fuel table

The generated file is `data/processed/patch_static_features.csv`.

Columns:

- `patch_id`
- `elev_m`
- `slope_deg`
- `aspect_deg`
- `fuel_model`
- `fuel_source`

Generated state:

- 2,061 rows
- 2,061 unique patch IDs
- exactly matches the patch IDs in `data/grid.geojson`
- elevation range: 324.616–2058.384 m
- slope range: 0.000–29.788 degrees
- aspect range: 0.474–359.388 degrees
- 10 patches have `aspect_deg = null` for flat/no-directed-aspect conditions

Aggregation rules:

- Elevation: mean valid LANDFIRE elevation pixel
- Slope: mean valid LF2020 slope-degree pixel
- Aspect: circular mean of non-flat values in the `0–359` degree range
- Fuel: most common valid LF2025 FBFM40 numeric code
- Missing values: `null`

Build command:

```powershell
python scripts/build_patch_static_features.py
```

Optional explicit arguments:

```powershell
python scripts/build_patch_static_features.py --dem <elev.tif> --slope <slopedeg.tif> --aspect <aspect.tif> --landfire <fbfm40.tif>
```

The script defaults to the downloaded LANDFIRE folders.

## Raw LANDFIRE data

LANDFIRE rasters are stored locally at `data/raw/landfire/`, which is ignored
by Git.

Downloaded folders:

- `LF2020_Elev_CONUS`
- `LF2020_SlpD_CONUS`
- `LF2020_Asp_CONUS`
- `LF2025_FBFM40_CONUS`
- `LF2025_CC_CONUS`
- `LF2025_CH_CONUS`
- `LF2025_CBH_CONUS`
- `LF2025_CBD_CONUS`

All eight files use EPSG:5070, 30 m pixels, identical clipped dimensions, and
the same extent.

Each folder includes a `.tif`, VAT `.dbf`, `metadata.xml`,
`output_parameters.txt`, and GIS sidecars. The folders total approximately
27 MB.

Raster encodings:

- Elevation: 275–2346 m; nodata `-9999`
- Slope: actual units are degrees; valid clipped values observed `0–65`
- Aspect: `-1` is flat, `0` is north, `90` east, `180` south, `270` west
- FBFM40: numeric Scott and Burgan fuel-model code
- CC: `0` is non-forested
- CH: `0` is non-forested
- CBH: `0` is non-forested
- CBD: `0` is non-forested
- 2025 canopy rasters: TIFF nodata `32767`
- 2025 DBFs: Fill-NoData `-9999`

Only Elevation, Slope, Aspect, and FBFM40 are currently used in
`patch_static_features.csv`. CC/CH/CBH/CBD are downloaded but not integrated.

The alignment names XGBoost/LightGBM, while M1 uses
HistGradientBoostingClassifier. Neither model is chosen for M3 training yet.
